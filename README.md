# OthelloAction.py について

### 定数・設定値（全体挙動のパラメータ）

- 盤面サイズや石の表現（黒/白/空）を定義する
- 角・辺・X マス・C マスなど、戦略上重要なマス集合を定義する
- 探索深さ（序盤〜終盤）、終盤完全探索に切り替える条件、静止探索の深さを定義する
- パスの価値（テンポ）を評価へ反映するためのボーナス値を定義する
- ノード上限を定義し、思考が暴走しないようにする
- 辺の確定石（ロック）評価の重みや発動条件を定義する
- 相手の X/C 癖観測（OBS）の有効/無効、観測量、補正率などを定義する
- 統計（STAT）とキャッシュ（CACHE）の有効/無効、およびキャッシュ最大サイズを定義する

### 状態・キャッシュ・統計（高速化と計測）

- \_moves_cache は「盤面 + 手番色」から合法手一覧を再利用するキャッシュ
- \_exec_cache は「盤面 + 手番色 + 着手」から着手後盤面を再利用するキャッシュ
- \_tt は通常探索（negamax）用の置換表（トランスポジションテーブル）
- \_exact_tt は終盤完全探索（exact_solve）用の置換表
- \_node は探索ノード数を数えるカウンタで、ノード上限に到達したら探索を打ち切る
- \_stat は getMoves/execute の呼び出し回数・ヒット率・探索時間などを計測する

### 盤面操作ユーティリティ

- fast_copy(board)
- 盤面のディープコピーを作り、探索中の副作用を避ける
- board_key(board)
- 盤面を不変なタプル形式に変換し、辞書キーとして使えるようにする

### キャッシュ管理

- \_cache_maybe_clear()
- キャッシュが大きくなりすぎた場合に全クリアしてメモリと速度劣化を抑える

### 合法手生成と着手実行（OthelloLogic ラッパ）

- get_moves(board, color)
- 合法手を返す（キャッシュ有効時は再利用し、統計も更新する）
- execute(board, move, color)
- 指定手を盤面に適用した新盤面を返す（キャッシュ有効時は再利用し、統計も更新する）

### 盤面集計・局面判定

- count_discs(board)
- 黒/白/空の数を数える（終盤判定・石差評価に使用）
- detect_new_game(board)
- 盤面が初期局面に近いかを判定し、新しい対局として内部状態を初期化するトリガにする
- infer_my_color(board)
- 盤面の石数から自分の色（黒/白）を推定して内部状態として保持する
- is_terminal(board)
- 黒白双方に合法手がない終局かどうかを判定する
- final_diff(board, me)
- 終局時の石差（自分視点）を返す（終盤完全探索の勝敗評価に使用）

### 相手に角を与えるかの検出

- gives_opponent_corner(board_after, opp_color)
- 自分の着手後、相手に角が打てるかを判定する（危険手の判定・並び替え・静止探索対象に使用）

### 相手の着手推定（観測用）

- detect_opp_placed(prev_board, cur_board, my_color)
- 前回盤面と現在盤面の差から、相手が新たに置いたマスを推定する
- 相手が X/C に置いたかを観測し、相手傾向（OBS）更新に使う

### 辺・確定石の評価要素（局所形状を評価）

- stable_edge_score(board, me)
- 角を取った後に角から連続して確定しやすい辺の伸びを評価する（安定辺のボーナス）
- count_locked_corner_edges(board, me)
- 角を起点に連続して自分色になっている辺/列の「確定に近い本数」を数える
- count_locked_full_edges(board, me)
- 辺が全て埋まっていて両端が空でない場合に、その辺における自分石の数を数える（終盤寄りの確定評価）
- eval_edge_line(line, me)
- 1 本の辺を一次元配列として見て、角起点の連続や硬直（空きが少ない）など形状を評価する
- edge_shape_score(board, me)
- 上下左右 4 辺に eval_edge_line を適用し、辺の形状から事故（硬直・相手支配）を避けるための補助評価を作る

### 盤面評価関数（AI の価値観）

- evaluate(board, me)
- 局面のスコアを算出する総合評価関数
- 主な要素
- 石差（終盤ほど重視）
- モビリティ（自分合法手数 − 相手合法手数）
- 角の保持（最重要）
- 辺の保持（角を除く辺石）
- 安定辺（stable edge）
- 角起点ロック辺（locked corner edges）
- 全埋まり辺のロック評価（条件付き）
- X/C マスの危険・寄付評価（角未確保の X/C を強く罰し、角確保時は緩和）
- 辺の形状評価（硬直や相手支配の兆候を嫌う）
- 相手傾向観測（OBS）に応じた X/C 罰点の動的調整
- 目的は「角献上や辺事故を避けつつ、手数と安定を確保する」こと

### 探索深さの選択

- choose_depth(e)
- 空きマス数に応じて探索深さを変える（終盤ほど深く読む）

### 手の並び替え（探索効率を上げる）

- move_order_key(board, move, to_play)
- 手に優先順位を付け、良い手から探索するためのキーを返す
- 角を最優先し、相手に角を与えないこと、モビリティ改善、X/C の危険度などを反映する

### 終盤完全探索へ切り替える判定

- should_exact_solve(board, to_play)
- 空きマスが少なく、分岐も少ないなどの条件で「終盤は完全探索で解くべき」と判断する
- 角が打てる・パスが絡むなど、勝敗が読み切りやすい条件を重視する

### ノード制限

- bump_node()
- 探索ノードを加算し、上限を超えたら探索を打ち切るための判定を返す

### 終盤完全探索（勝敗を読み切る）

- exact_solve(board, to_play, me, alpha, beta, prev_pass=False)
- 終盤用の αβ 探索で、評価ではなく最終石差（勝敗）を主目的に読み切る
- パスが連続したら終局として確定評価にする
- パスの価値（テンポ）をボーナスとして反映し、相手に連続手番を与えることを嫌う
- 専用置換表 \_exact_tt により同一局面を再計算しない

### 静止探索（評価が揺れやすい局面を追加で読む）

- qsearch(board, to_play, me, alpha, beta, depth_q)
- 探索深さが尽きた局面で、角・X/C・角献上などの「危険/決定的な手」だけ追加で読む
- 見た目の評価が安定するまで、限定的に先読みして評価の誤差を減らす

### 通常探索（中盤の主力）

- negamax(board, to_play, me, depth, alpha, beta, prev_pass=False)
- negamax 形式の αβ 探索で最善スコアを計算する
- 合法手なしのときはパス処理を行い、連続パスで終局判定にする
- 終盤条件を満たせば exact_solve に切り替える
- 深さ 0 になれば qsearch を呼び、評価の揺れを抑える
- 置換表 \_tt により同一局面を再計算しない

### ルートでの手選択

- choose_move(board, moves, me)
- 角が打てるなら即座に角を選ぶ
- 空きマス数から探索深さを決める
- 合法手を並び替えて順に探索し、最も良い手を選ぶ
- 相手に角を与える手は追加で評価を下げ、選ばれにくくする

### エントリポイント（対局管理・観測・出力

- getAction(board, moves)
- 対局開始直後（新しいゲーム）を検出し、置換表・キャッシュ・観測状態を初期化する
- 初回呼び出しで自分の色を推定し、内部状態として保持する
- 前回盤面との差分から相手の着手位置を推定し、X/C 傾向（OBS）を更新する
- 終局または合法手なしの場合はパス相当の返り値を返す
- 探索ノード数をリセットし、choose_move により最終手を決める
- 統計が有効なら、思考時間・ノード数・キャッシュヒット率などをログ出力す
